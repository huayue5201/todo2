1. INTRODUCTION                                                *todo2-intro*

todo2.nvim is an engineer-oriented task management plugin with bidirectional
links between code and TODO files.

- Code is the source of tasks: create tasks on code lines; the enclosing code
  block (function/class/method) is recorded automatically.
- TODO files are the management UI: hierarchy, status and archiving.
- Both stay in sync: status, content, line numbers and context changes are
  synchronized automatically.

Code files render task status next to linked lines via extmark virtual text;
TODO files manage tasks through task lines.

==============================================================================
2. REQUIREMENTS / INSTALL                                   *todo2-install*

Dependencies:
- Neovim (with Treesitter and LSP recommended for best code-block detection)
- nvim-store3 (persistent storage)

With lazy.nvim: >
    {
        "huayue5201/todo2",
        lazy = true,
        dependencies = { "nvim-store3" },
        name = "todo2",
        config = function()
            require("todo2").setup()
        end,
    }
<

3. SETUP & CONFIGURATION                                      *todo2-config*

                                                          *todo2.setup()*
All options are top-level keys. Example: >
    require("todo2").setup({
        conceal_enable = true,
        -- Hide the inline `@YYYY-MM-DD` and show the due date in the end-of-line
        -- metadata band instead (`<icon> 11-02 · ↻10-30`). The raw date stays
        -- hidden until the cursor sits on it (so the line reads content-first);
        -- the file text is never changed.
        conceal_due = true,

        -- 循环（活跃）状态：顺序即循环顺序，第一个为默认状态。
        -- label 同时是 TODO 文件里的标记前缀，已有任务后改名会让标记失联。
        status = {
            cycle = {
            { label = "todo", icon = " ", color = "#51cf66" },
            { label = "fix", icon = "󱁤 ", color = "#ff6b6b" },
            { label = "refactor", icon = "󱑟 ", color = "#ffd43b" },
            },
        },

        -- 任务正文（任务行下方的缩进续行）
        description = {
            fold = true, -- 在 TODO 文件里默认折叠正文
        },

        -- 代码文件里的任务渲染
        code_render = {
            position = "above", -- "inline" | "above" | "below"
            max_lines = 3,      -- 同一代码行最多展示的任务数
            -- above/below 虚拟行超出窗口时："trunc"（默认，不随横滚）|
            -- "scroll"（nowrap 时随代码横滚）| "auto" | "wrap"
            virt_lines_overflow = "trunc",
        },

        parser = {
            indent_width = 2,
            empty_line_reset = 1,
            context_split = false,
        },

        -- shared by TODO rows / drawer / code rows / statistics footer
        progress_bar = {
            style = "full",
            chars = { filled = "▰", empty = "▱" },
            length = { min = 5, max = 20 },
            highlights = {
                done = "Todo2ProgressDone",
                todo = "Todo2ProgressTodo",
            },
        },

        checkbox_icons = {
            todo = "◻",
            done = "✔",
            archived = "📦",
        },

        viewer_icons = {
            indent = {
                top    = "│ ",
                middle = "├─",
                last   = "└─",
                ws     = "  ",
            },
        },

        viewer_show_icons = true,
        viewer_show_child_count = true,
        viewer_file_header_style = "─ %s ──[ %d tasks ]",

        drawer = {
            position = "right",
            width = 40,
            height = 12,
            focus_on_jump = false,
        },

        archive_section = {
            title_prefix = "## Archived",
        },

        -- Archive: archiving moves the tree's lines into the
        -- `## Archived (YYYY-MM)` section of the TODO file and sets the task
        -- status to archived (tasks stay in the store). The section is the
        -- single source of truth. See :TodoArchive.
        archive = {
            allow_unfinished = true,
            include_in_render = false,
            auto_after_days = 0,
        },

        -- Orphan GC: when a TODO file (and any code anchor) is deleted
        -- outside the plugin, the task is quarantined into the
        -- facts.orphan.* bucket instead of being lost. It is restored
        -- automatically if the file comes back, and purged only after
        -- retention_days. See :TodoDoctor!.
        orphan = {
            enabled = true,
            retention_days = 30,
        },

        -- Reconcile: the .todo.md file is the single source of truth; the
        -- store is only a cache. Opportunistic sync can miss events and
        -- drift, so a full reindex of every TODO file runs on startup.
        -- See :TodoReconcile.
        sync = {
            reconcile_on_start = true,
        },

        todo_files = {
            extensions = { ".todo.md", ".todo", ".todo.txt" },
            filenames  = { "todo.txt" },
            globs      = { "*.todo.md", "*.todo", "*.todo.txt", "todo.txt" },
            default_ext = ".todo.md",
        },

        file_template = {
            default_content = { "## Active" },
        },

        -- Calendar (see :TodoCalendar)
        calendar = {
            first_day_of_week = "monday", -- "monday" | "sunday"
            mark_icon = "●", -- unfinished-task counter dot (green + count)
            done_icon = "○", -- completed-task counter dot (grey + count)
            winblend = 0,    -- float transparency (0 = opaque; >0 shows text below)
            show_completed = true, -- false = hide completed tasks entirely
        },
    })
<
Named filters (`:TodoFilter save NAME`) are persisted per project in
`.todo2/config.json`; config passed to `setup()` takes precedence.

4. COMMANDS                                                *todo2-commands*

                                                    *:TodoSync*
:TodoSync       Manually sync the current TODO file.

                                                    *:TodoDel*
:TodoDel        Smart-delete a task under the cursor (a hand-written task line
                without an id is deleted as a line, together with its body).
                A range deletes in bulk: `:'<,'>TodoDel` takes the whole visual
                selection (each selected task with its subtree), `:5,9TodoDel`
                a line range. A single line refuses when the task still has
                children — use `:TodoDel!` to delete it with the whole
                subtree (like the drawer `<BS>`), `:TodoPromote` to keep the
                children, or pass a range so the same subtree goes in one go.
                In a code buffer it deletes the task linked to that line, never
                the code.

                                                    *:TodoPromote*
:TodoPromote    Delete the task under the cursor but keep its children: they are
                re-parented to its parent and their indentation drops one step.
                Never leaves orphan tasks behind. In a code buffer this applies
                to the task linked to the current line (code is not modified).

                                                    *:TodoReconcile*
:TodoReconcile  Full reconcile (reindex) of every TODO file in the project:
                the file is the source of truth, the store is a cache.

                                                    *:TodoArchive*
:TodoArchive    Archive the task group at the cursor: its lines move into the
                `## Archived (YYYY-MM)` section and the status becomes archived
                (tasks stay in the store, the section is the source of truth).
                Reversible; ids are preserved. With `!`, archive even when the
                group contains unfinished tasks (overrides
                `archive.allow_unfinished`).

                                                    *:TodoUnarchive*
:TodoUnarchive  Pick an archived group and move it back into the active
                section of its TODO file.

                                                    *:TodoArchiveView*
:TodoArchiveView
                Show archived tasks as a tree in the QuickFix list.

                                                    *:TodoArchiveQF*
:TodoArchiveQF  List archived task anchors (flat) in the QuickFix list.

                                                    *:TodoFilter*
:TodoFilter [conditions]
                Show only tasks matching the conditions (all AND): plain
                words are tags, `status:<label|active>` (repeatable = OR),
                `path:<substring|glob>`,
                `due:today|tomorrow|week|month|overdue|none|YYYY-MM[-DD]`
                (also `<DATE`, `<=DATE`, `>DATE`, `>=DATE`). Ancestors/
                descendants stay for context. No argument or `!` clears the
                filter.
:TodoFilter save NAME [conditions]
                Save a named filter (defaults to the active one).
:TodoFilter @NAME
                Apply a saved filter.
:TodoFilter list / delete NAME
                List or delete saved filters. Saved filters live in the
                `filters` config table.

                                                    *:TodoDue*
:TodoDue [date|none]
                Set the due date (`@YYYY-MM-DD`, a date-only field written
                after the task marker and before the tags) on the cursor
                task. Accepts YYYY-MM-DD, YYYY/MM/DD, YYYYMMDD, today,
                tomorrow, +7d, -1d. No argument prompts (prefilled with the
                current value); `none` clears it. The date is coloured by
                urgency (overdue / due today / later) and can be filtered
                with `due:`.
                Only a date right after the task marker counts; `@date`
                written at the end of the title stays plain text. Rewriting
                such a line emits a warning instead of failing silently.

                                                    *:TodoCalendar*
':TodoCalendar [YYYY-MM] [day]
                Open the calendar float for the current project.
                All labels in the calendar float are English (no i18n).
                  • Month view -- every day is its own background-coloured
                    block (no border characters). Line 1 holds the day number,
                    pinned to the first column so it never shifts, plus the
                    counters right-aligned: `● 2` = unfinished (green), `○ 1` =
                    completed (grey); a counter is omitted when zero and counts
                    above 9 render as `9+`. Line 2 shows the title of the most
                    urgent open task (`▎` bar + truncated title). Busy days get
                    a heavier tint (3 levels), today's date is highlighted as text
                    (accent colour + bold, no background block),
                    the selected day gets a brighter whole-cell block.
                    Completed tasks stay visible so "was due, done late"
                    remains auditable; archived tasks (`[>]`) are left out, and
                    adjacent-month days are rendered dimmed and uncounted.
                    A trailing week that belongs entirely to the next month is
                    trimmed. If the screen is too small for the grid, the month
                    degrades to a compact one-line-per-week layout.
                  • Side panel -- when `columns >= 116`, a panel for the
                    selected day (counts + task list) is appended to the right
                    of the grid and follows `j` / `k`.
                  • `h` / `l` previous/next day and `j` / `k` previous/next
                    week move the selection inside the rendered grid: you can
                    step onto the dimmed adjacent-month cells, and the month
                    only flips once the selection leaves the grid. `H` / `L`
                    previous/next month, `t` today, `q` / `Esc` close.
                  • `f` / `F` set / clear a task filter (same syntax as
                    `:TodoFilter`: `#tag`, `status:label`, `path:substr`,
                    `due:overdue`). It only affects the float and is shown in
                    the title line.
                  • `<CR>` on a day opens the day list: the tasks due that
                    day (project scope, subtasks included), unfinished first
                    then completed (rendered grey), with an open/done summary
                    line. `<CR>` jumps to the task's code anchor (the TODO line is only a
                    fallback when nothing is linked), `s` / `>` postpones
                    the selected task (overdue/today -> today, future -> +1
                    day), `b` / `Esc` goes back to the month view, `q` closes.
                  • The float sizes itself to its content (width and height)
                    and stays centred, re-centring on `VimResized`. Other
                    plugins' decorations (indent guides, sign/fold columns,
                    statuscolumn, spell, treesitter-context, ...) are disabled
                    inside the float.
                Accepts `YYYY-MM` (and an optional day) as arguments, e.g.
                `:TodoCalendar 2026-10` or `:TodoCalendar 2026-10-15`.
                Config: `calendar = { first_day_of_week = "monday",
                mark_icon = "●", done_icon = "○", winblend = 0,
                show_completed = true }`. With `show_completed = false`,
                completed tasks are hidden from the grid, the counters and the
                panels.

                                                    *:TodoSort*
:TodoSort [status|default]
                Sort drawer siblings by the configured status cycle
                (completed/archived last); no argument toggles.

                                                    *:SmartPreview*
:SmartPreview   Smart-preview TODO/code.

                                                    *:TodoDesc*
:TodoDesc       Edit the task description (body). In a TODO file it edits
                inline: it opens the fold, puts the cursor in the body under
                the task (creating an indented line if none) and enters insert
                mode. On a code line linked to a task (or from the drawer) it
                uses a multi-line floating window. The body lives in the TODO
                file as indented continuation lines under the task line.

                                                    *:TodoLink*
:TodoLink [id]  Bind the current code line to an existing task. Without {id},
                pick one from the current project's tasks.

                                                    *:TodoContext*
:TodoContext [markdown|json]
                Assemble the current task's context for an LLM: content /
                description / status, the code anchor (path, line, optional
                0-based byte column, block type/name/signature and source),
                and the task tree (ancestor
                chain + subtasks). Copies Markdown to the clipboard by
                default; `json` emits JSON. With `!`, open it in a scratch
                buffer instead of copying.

                                                    *:TodoMcp*
:TodoMcp        Print the MCP setup info for wiring the todo2 MCP server into
                an MCP client such as pi: the Neovim RPC socket, the bridge
                script path, and a ready-to-run `pi mcp add` command. The
                server exposes five action-dispatch tools: task_query
                (action = list / search / tree / info / context; marked
                readOnly), task_create (action = task / tree / note / file),
                task_update (action = content / status / tags_set / tags_add /
                tags_remove), task_link (action = link / verify /
                complete_commit), and task_remove (action = delete / archive /
                unarchive). Each tool requires an action plus that tool's flat
                params; missing required params are reported at runtime.
                `task_query/list` / `task_query/search` support status/tag
                filters, limit/offset pagination and include_archived;
                `task_create/note` creates an anchor-less item while
                `task_create/task` requires a code anchor
                (`{path,line,col?}`; line is 1-based, col is an optional
                0-based byte offset). The array-returning
                actions (task_query/list, task_query/search) return their
                array wrapped as `structuredContent.items` (the MCP spec
                requires structured content to be a JSON object, not an
                array). Set TODO2_MCP_READONLY=1 for read-only mode; set
                TODO2_PROJECT=name to pin the bridge to one project's instance
                when several Neovim instances are open. Set
                TODO2_MCP_STANDALONE=1 to run without a live Neovim: the todo2
                data layer boots inside the server process, the TODO files on
                disk are the source of truth, and the project dir comes from
                the server's cwd (override with TODO2_PROJECT_DIR). `task_create/task` is
                idempotent by default: the same content under the same parent
                reuses the existing task (`allow_duplicate: true` forces a new
                one).

5. KEYMAPS                                                  *todo2-keymaps*

The plugin itself ships only `:TodoXxx` commands; global `<leader>m*` mappings
are user-configured (see the examples below / README). Each group key
(`<leader>m<group>`) is a pure prefix that is never itself mapped, so groups
never delay each other; actions are `<leader>m<group><action>`.

Global (example mapping): >
    <CR>        toggle task status (completed ↔ not completed)
    <S-tab>     cycle status
    <BS>        smart-delete a task
    <BS> (visual) delete every selected task in one go (subtrees included)
    <S-CR>      edit the linked TODO task content from code
    <C-,>       dynamic jump TODO ↔ code
    <leader>mfn create TODO file
    <leader>mfr rename TODO file
    <leader>mfd delete TODO file
    <leader>mta create a task from code
    <leader>mts select task status (menu)
    <leader>mtd edit task description (body)
    <leader>mtt add/remove/set tags
    <leader>mtf filter TODOs by tag/status/path (! clears)
    <leader>mtc copy task context (Markdown, for AI)
    <leader>mtl link code ↔ task
    <leader>maa archive task group (into `## Archived`)
    <leader>mau restore (unarchive) a task group
    <leader>mav show archived tasks as a tree (QuickFix)
    <leader>maq show archived tasks flat (QuickFix)
    <leader>mvc open the project calendar (`:TodoCalendar`)
    <leader>mvd open the task-tree drawer (`:TodoDrawer`)
    <leader>mvf open TODO file in floating window
    <leader>mvs open in horizontal split
    <leader>mvv open in vertical split
    <leader>mve open in edit mode
    <leader>mvp preview tasks for the current code line (`:SmartPreview`)
    <leader>mla show all bidirectional-link markers (QuickFix)
    <leader>mlb show markers in current buffer (LocList)
    <leader>mgs git: sync commits and apply task refs
    <leader>mgr git: pre-commit self-review of dirty anchors
    <leader>mgb git: show anchor history
<
Inside a TODO file: >
    q               close window
    <C-r>           refresh display
    v / x + <CR>    batch-toggle status of selected tasks
    <localleader>n       new task
    <localleader>nc      new subtask
    <localleader>ns      new sibling task
<
In the calendar (`:TodoCalendar`): >
    h / l           previous / next day (selects inside the grid)
    j / k           previous / next week
    H / L           previous / next month
    t               jump to today
    <CR>            open the day list (then jump to the task's code anchor,
                    falling back to its TODO line)
    s / >           day list: postpone the selected task
    f / F           set / clear a task filter
    b / <BS> / Esc  day list -> month view
    q               close
<
In the task-tree drawer (`:TodoDrawer`): >
    <CR>            toggle task status
    <S-CR>          cycle status
    t               select task status (menu)
    f               filter by tag / status: / path: (prompt)
    F               clear the filter
    s               sort siblings by status (toggle)
    <Tab>           jump to task location (linked code, else TODO line)
    o               preview the TODO file in a float
    P               preview the task's linked code lines
    e               edit task content
    E               edit task description (body)
    c               copy the task context (Markdown, for AI)
    C               open the calendar on the task's due date (today if none)
    y               yank the task subtree to the task register
    d               cut the task subtree to the task register
    p               paste the task (child of cursor's task / at file end)
    a               new TODO file
    R               rename the current file group's TODO file
    D               delete the current file group's TODO file
    <BS>            delete task
    <BS> (visual)   delete every selected task in bulk (subtrees included)
    x               archive the task group (unarchive if on an archived task)
    za/zo/zc        fold / unfold / collapse the current node
    zR/zM           expand / collapse all
    r               refresh
    A               toggle archived tasks in the tree
    ?               toggle this help
    q               close the drawer
<

6. TASK LINE FORMAT                                          *todo2-format*

Task lines use this format: >
    - [ ] <status>:<id> task content
             optional description (indented continuation lines)
<
- Prefixes `- `, `* ` and `+ ` are supported.
- Checkboxes: `[ ]` (todo), `[x]` / `[X]` (done), `[>]` (archived).
- `<status>` is a cycle label (`todo` / `doing` / `blocked` by default);
  `<id>` is a 6-character base36 ID.
- `[>]` marks an archived task. Archived tasks live in the
  `## Archived (YYYY-MM)` section and normally do not appear in the default
  views; restore them with `:TodoUnarchive`.
- Lines indented deeper than a task line form its *description* (body); they
  end at the next task line, or at a line that is not indented deeper.
- Bodies are collapsed by default in TODO files (`za` / `zR` to expand).
- Deleting a task also removes its body: body and task are strongly bound.

Example: >
    ## Active
    - [ ] todo:ab12cd fix login logic
          needs to also handle empty input

          see `src/http_client.rs`
      - [x] completed:34ef56 handle empty input
    - [ ] doing:78ab90 add documentation

    ## Archived (2026-09)
    - [>] completed:cd34ef completed task
<
No text markers are inserted into code files; code links are maintained in
the store's `locations.code` and rendered through extmark virtual text.

7. WORKFLOWS                                              *todo2-workflows*

CREATE A TASK FROM CODE ~

1. Put the cursor on the code line to link.
2. Press `<leader>mta`.
3. Choose a tag → choose a TODO file.
4. The task is written to the TODO file with the code location and enclosing
   code-block context recorded.

TOGGLE STATUS IN CODE ~

With the cursor on a linked line in a code file, press `<CR>` to toggle the
completed status; the code-side marker updates immediately.

ARCHIVE A TASK GROUP ~

Archiving is a move, not a discard: the task group's lines are moved into the
`## Archived (YYYY-MM)` section of the TODO file and their status becomes
archived (they stay in the store). The section is the single source of truth;
the operation is reversible (ids are preserved, statuses restored on
`:TodoUnarchive`). Code files are never modified; anchors are frozen and
re-resolved when shown. Use `:TodoArchiveView` / `:TodoArchiveQF` to review
archived tasks, and the drawer key `A` to include them in the tree.

DATA-SHAPE CONTRACT ~

The *.todo.md files are the source of truth: anything derived from them is rebuilt
by reconcile, so old store namespaces are simply hard-cut. Only the data that
cannot be rebuilt (timestamps, delete tombstones, orphan snapshots, anchor
verification) is protected.

  store/schema.lua        single normalization entry: legacy fields stripped,
                          defaults filled, invalid dates/unknown statuses
                          dropped, locations validated (normalize_task /
                          normalize_facts)
  facts.meta.schema_version   marks which shape wrote the data (currently 1);
                          marking only, it never converts anything
  test/schema.lua         asserts schema.TASK_CONTRACT — add a field without a
                          default and it fails

Additive changes (new field / new key) need no migration, only a default. Real
migrations (data.json backup + `:TodoMigrate`) are built when a change is
incompatible: renamed keys, changed semantics (timestamp units, fingerprint
algorithm), split/merged dictionary sets. TODO file syntax changes are never
migrated: parse compatibly, write back in the new format.
