==============================================================================
1. INTRODUCTION                                                *todo2-intro*

todo2.nvim is an engineer-oriented task management plugin with bidirectional
links between code and TODO files. It makes tasks "belong" to code, turning
TODO files into a natural extension of the codebase:

- Code is the source of tasks: create tasks on code lines; the enclosing code
  block (function/class/method) is recorded automatically.
- TODO files are the management UI: hierarchy, status and archiving.
- Both stay in sync: status, content, line numbers and context changes are
  synchronized automatically.
- Rendering is event-driven: every change is reflected immediately, with no
  manual refresh.

Code files render task status next to linked lines via extmark virtual text;
TODO files manage tasks through task lines.

==============================================================================
2. REQUIREMENTS / INSTALL                                   *todo2-install*

Requirements:
- Neovim 0.13+ (uses `vim.async`; Treesitter and LSP recommended for best
  code-block detection)
- nvim-store3 (persistent storage): https://github.com/huayue5201/nvim-store3

With lazy.nvim: >
    {
        "huayue5201/todo2",
        dependencies = { "huayue5201/nvim-store3" },
    }
<
Lazy loading is handled by the plugin itself: `plugin/todo2.lua` only
registers commands, fallback keys and TODO-file detection; the real
initialization (`require("todo2").setup()`) runs the first time a TODO file is
opened or a command/key is used. No `lazy` / `config` / `event` needed.

3. SETUP & CONFIGURATION                                      *todo2-config*

                                                          *todo2.setup()*
All options are top-level keys. Set them before the plugin loads, either via
`vim.g.todo2_config` or by calling `require("todo2").setup({...})`. Example: >
    vim.g.todo2_config = {
        -- Core
        conceal_enable = true,
        -- Interactive due-date entry: true = three-box date panel,
        -- false = one-line expression prompt (see |todo2-due-panel|).
        due = { panel = true },
        -- Hide the inline `@YYYY-MM-DD` and show the due date in the end-of-line
        -- metadata band instead (`● ↻10-30 · 11-02`). The raw date stays
        -- hidden until the cursor sits on it (so the line reads content-first);
        -- the file text is never changed.
        conceal_due = true,

        -- 循环（活跃）状态：顺序即循环顺序，第一个为默认状态。
        -- label 同时是 TODO 文件里的标记前缀，已有任务后改名会让标记失联。
        status = {
            cycle = {
            { label = "todo", icon = " ", color = "#51cf66" },
            { label = "doing", icon = "▶ ", color = "#f5c2e7" },
            { label = "blocked", icon = "⛔ ", color = "#ff6b6b" },
            },
        },

        -- 任务正文（任务行下方的缩进续行）
        description = {
            fold = true, -- 在 TODO 文件里默认折叠正文
            format_on_save = true, -- 保存时把正文缩进规整到列表项内容列
        },

        -- 代码文件里的任务渲染
        code_render = {
            position = "above", -- "inline" | "above" | "below"
            max_lines = 3,      -- 同一代码行最多展示的任务数
            -- above/below 虚拟行超出窗口时："trunc"（默认，不随横滚）|
            -- "scroll"（nowrap 时随代码横滚）| "auto" | "wrap"
            virt_lines_overflow = "trunc",
        },

        -- :TodoView preview
        preview = {
            max_blocks = 20, -- safety cap; geometry decides the real count
        },

        parser = {
            indent_width = 2,
            empty_line_reset = 1,
            context_split = false,
        },

        -- shared by TODO rows / drawer / code rows / statistics footer
        progress_bar = {
            style = "full",
            chars = { filled = "▰", empty = "▱" },
            length = { min = 5, max = 20 },
            highlights = {
                done = "Todo2ProgressDone",
                todo = "Todo2ProgressTodo",
            },
        },

        checkbox_icons = {
            todo = "◻",
            done = "✓",
            archived = "📦",
        },

        viewer_icons = {
            indent = {
                top    = "│ ",
                middle = "├─",
                last   = "└─",
                ws     = "  ",
            },
        },

        viewer_show_icons = true,
        viewer_show_child_count = true,
        viewer_file_header_style = "─ %s ──[ %d tasks ]",

        -- Task-tree drawer (:TodoDrawer)
        drawer = {
            position = "right",     -- "right" | "bottom"
            width = 40,             -- width when position = "right"
            height = 12,            -- height when position = "bottom"
            focus_on_jump = false,  -- true: move focus to code after <CR>
            expand_lines = true,    -- float-complete the cursor line when it overflows
        },

        -- Calendar (:TodoCalendar)
        calendar = {
            first_day_of_week = "monday", -- "monday" | "sunday"
            mark_icon = "●",              -- unfinished counter dot (green + count)
            done_icon = "○",              -- completed counter dot (grey + count)
            winblend = 0,                 -- float transparency (0 = opaque)
            show_completed = true,        -- false = hide completed tasks entirely
        },

        -- Named filters (:TodoFilter save NAME ...) are persisted per project.
        filters = {},

        -- Archive section title prefix (any `(YYYY-MM)` suffix is accepted)
        archive_section = {
            title_prefix = "## Archived",
        },

        -- Archive: archiving moves the tree's lines into the
        -- `## Archived (YYYY-MM)` section of the TODO file and sets the task
        -- status to archived (tasks stay in the store). The section is the
        -- single source of truth. See :TodoArchive.
        archive = {
            allow_unfinished = true,     -- allow archiving a tree with active tasks
            include_in_render = false,   -- drawer shows archived tasks by default
            auto_after_days = 0,         -- auto-archive completed groups after N days
        },

        -- Orphan GC: when a TODO file (and any code anchor) is deleted
        -- outside the plugin, the task is quarantined into the
        -- facts.orphan.* bucket instead of being lost. It is restored
        -- automatically if the file comes back, and purged only after
        -- retention_days. See :TodoDoctor!.
        orphan = {
            enabled = true,
            retention_days = 30, -- 0 = never auto-purge
        },

        -- Reconcile: the .todo.md file is the single source of truth; the
        -- store is only a cache. Opportunistic sync can miss events and
        -- drift, so a full reindex of every TODO file runs on startup.
        -- See :TodoSync!.
        sync = {
            reconcile_on_start = true,
        },

        -- TODO file detection (extensible to any format)
        todo_files = {
            extensions = { ".todo.md", ".todo", ".todo.txt" }, -- suffix match
            filenames  = { "todo.txt" },                        -- exact filename
            globs      = { "*.todo.md", "*.todo", "*.todo.txt", "todo.txt" },
            default_ext = ".todo.md",                           -- default for new files
        },

        -- New-file template
        file_template = {
            default_content = { "## Active" },
        },

        -- Task context (for AI / external tools)
        ai = {
            enabled = false,          -- publish the MCP endpoint on setup (default: off)
            include_code = true,      -- include the code block body
            include_ancestors = true, -- include the ancestor chain
            include_children = 1,     -- subtree levels: true = all, N = levels
            max_code_lines = 200,     -- max code lines (0 = unlimited)
        },

        -- Git integration: turn task references in commit messages into status.
        -- Off by default; enable explicitly.
        git = {
            enable = false,        -- master switch (:TodoGit sync! bypasses it)
            trigger = "manual",    -- "manual" | "on_open"
            show_metadata = true,  -- show the linked commit in viewer / drawer
            refs = {
                { pattern = "[Tt]odo[:：]%s*([0-9a-z]+)", status = "completed" },
            },
        },
    }
<
Named filters (`:TodoFilter save NAME`) are persisted per project in
`.todo2/config.json`; config passed to `setup()` takes precedence.

TODO file detection: `.todo.md` / `.todo` / `.todo.txt` / `todo.txt` are
recognized by default; any extension can be added through `todo_files`.

4. COMMANDS                                                *todo2-commands*

---------------------------------------------------------------------
4.1 Unified entry                                                *:Todo*
                                                         *todo2-command-todo*

:Todo           With no argument, open/close the task-tree drawer (same as
                `:TodoDrawer`).
:Todo help      Open this help (`:h todo2`).
:Todo <sub> [args]
                Equivalent to `:Todo<Sub> [args]`. The subcommand is
                case-insensitive, accepts `!` and a line range, and offers
                subcommand completion. Examples: `:Todo calendar 2026-10`,
                `:Todo sync`, `:Todo del!`, `:'<,'>Todo del`.
                The subcommand list and descriptions are derived from the
                registered `:Todo*` commands, so they never drift. Grouped
                entries work too: `:Todo file new`, `:Todo view split`,
                `:Todo git review` (see |todo2-command-alias|).

---------------------------------------------------------------------
4.2 Core file / task commands                         *todo2-command-core*

Three groups collect the low-frequency commands; their members are documented
below and stay available under their old names (see |todo2-command-alias|):

  :TodoFile new|rename|delete       TODO file lifecycle
  :TodoView float|split|vsplit|edit|close|preview
  :TodoTask rename|desc|promote

Called without a subcommand a group prints its usage, an unknown subcommand is
rejected with the list of members, and completion offers the members.

                                                    *:TodoSync*
:TodoSync       Manually sync the current TODO file. With `!`, run a full
                reconcile instead: `:TodoSync!`.

                                                    *:TodoDoctor*
:TodoDoctor     Report isolated orphan tasks (files deleted outside the
                plugin). With `!`, force an orphan sweep:
                `:TodoDoctor!`.

                                                    *:TodoAdd*
:TodoAdd        Create a task from the current code line (choose a TODO file;
                the code location and enclosing code-block context are
                recorded).

                                                    *:TodoInsert*
:TodoInsert [task|sub|sibling]
                New independent task (plain checklist task, no context).
                `sub` creates a subtask of the current task, `sibling` creates
                a sibling of it; no argument is the same as `task`.

                                                    *:TodoLink*
:TodoLink [id]  Bind the current code line to an existing task. Without {id},
                pick one from the current project's tasks.

                                                    *:TodoToggle*
:TodoToggle     Toggle task status. With a line range or a Visual selection it
                toggles every selected task: `:'<,'>TodoToggle`.

                                                    *:TodoStatus*
:TodoStatus     Choose task status from a menu. With `!`, cycle straight to the
                next status: `:TodoStatus!`.

                                                    *:TodoDel*
:TodoDel        Smart-delete a task under the cursor (a hand-written task line
                without an id is deleted as a line, together with its body).
                A range deletes in bulk: `:'<,'>TodoDel` takes the whole visual
                selection (each selected task with its subtree), `:5,9TodoDel`
                a line range. A single line refuses when the task still has
                children — use `:TodoDel!` to delete it with the whole
                subtree (like the drawer `<BS>`), `:TodoTask promote` to keep the
                children, or pass a range so the same subtree goes in one go.
                In a code buffer it deletes the task linked to that line, never
                the code.

                                                    *:TodoTag*
:TodoTag [tags] Add / remove / set tags on the cursor task. No argument opens
                a multi-select menu (toggle tags, add a new one, clear the
                selection, then Apply; Esc discards). `:TodoTag fix backend`
                sets them, `:TodoTag +urgent` adds, `:TodoTag -bug` removes.
                Works on a TODO line or a code anchor.

                                                    *:TodoDue*
:TodoDue [date|none]
                Set the due date (`@YYYY-MM-DD`, a date-only field written
                after the task marker and before the tags) on the cursor
                task. Accepts YYYY-MM-DD, YYYY/MM/DD, YYYYMMDD, today,
                tomorrow, +7d, -1d. No argument opens the date panel (see
                |todo2-due-panel|, prefilled with the current value); with
                arguments it writes directly. `none` / `clear` / `-` clears
                the date, and so does an empty `due` over MCP. The date is
                coloured by urgency (overdue / due today / later) and can be
                filtered with `due:`.
                Only a date right after the task marker counts; `@date`
                written at the end of the title stays plain text. Rewriting
                such a line emits a warning instead of failing silently.

                                                *todo2-due-panel*
The date panel (any interactive due-date entry: `:TodoDue` without arguments,
`d` in |:TodoSet|, and `u` in the drawer) is one row of three fixed-width
input boxes — year / month / day — inside a small float.

     ╭─year─╮ ╭month╮ ╭─day─╮
       2026     11      02
     ╰──────╯ ╰─────╯ ╰─────╯
          → 2026-11-02  Mon
   t today   m tomorrow   w +1 week   x clear   e expression
      Tab next · Enter confirm · Esc leaves input · q cancels

Guard rails, cheapest first:
  - Typing: only digits are accepted, the year takes 4 characters and the
    month/day 2; a full box jumps to the next one automatically, and typing
    into a box that is already full replaces its content (no key is ever
    swallowed).
  - Value: out-of-range input is normalized as you type — month `13` becomes
    `12`, `02-31` becomes `02-28`, a year below 1970 is raised to 1970. The
    `→` line always shows the exact date that will be written, so nothing is
    silently changed on you.
  - Commit: all three boxes empty clears the due date; `q` / `Esc` `Esc`
    cancels without touching the task.

The row of boxes, the resulting date and the hints are all horizontally
centered, and each box centers its own digits. The panel opens below the
cursor and flips above it when there is not enough room left on screen.

Keys: `<Tab>` / `<S-Tab>` move between boxes (text boxes stay in insert
mode), `<CR>` writes, `t`/`m`/`w` fill today / tomorrow / +1 week, `x` empties
all three (commit to clear), `h`/`l` move between boxes in normal mode, and
`e` (or `<C-e>`) falls back to the one-line expression prompt for `+7d`,
`today` and friends. The year box may be left empty (= current year) or
filled with two digits (`27` = 2027).

Set `due = { panel = false }` to always use the one-line prompt.

                                                    *:TodoFilter*
:TodoFilter [conditions]
                Show only tasks matching the conditions (all AND). One rule
                covers the whole syntax: everything is `field:value`, and a
                bare word is shorthand for `tag:value` — so `fix` ==
                `tag:fix`, and `git:main` keeps working as a derived tag.
                Fields: `tag:<name>` (AND), `status:<label|active>` (repeatable
                = OR), `path:<substring|glob>`,
                `due:today|tomorrow|week|month|overdue|none|YYYY-MM[-DD]`
                (also `<DATE`, `<=DATE`, `>DATE`, `>=DATE`). Ancestors/
                descendants stay for context. No argument or `!` clears the
                filter.
:TodoFilter save NAME [conditions]
                Save a named filter (defaults to the active one).
:TodoFilter @NAME
                Apply a saved filter.
:TodoFilter list / delete NAME
                List or delete saved filters. Saved filters live in the
                `filters` config table.

                                                    *:TodoSort*
:TodoSort [status|default]
                Sort drawer siblings by the configured status cycle
                (completed/archived last); no argument toggles.

4.3 Archive                                          *todo2-command-archive*

                                                    *:TodoArchive*
:TodoArchive    Archive the task group at the cursor: its lines move into the
                `## Archived (YYYY-MM)` section and the status becomes archived
                (tasks stay in the store, the section is the source of truth).
                Reversible; ids are preserved. With `!`, archive even when the
                group contains unfinished tasks (overrides
                `archive.allow_unfinished`).

                                                    *:TodoUnarchive*
:TodoUnarchive  Pick an archived group and move it back into the active
                section of its TODO file (statuses restored).

                                                    *:TodoArchiveView*
:TodoArchiveView
                Show archived tasks as a tree in the QuickFix list. With `!`,
                list the flat archived anchors instead:
                `:TodoArchiveView!`.

4.4 Tags / due dates / filters                       *todo2-command-tags*

See |:TodoTag|, |:TodoDue| and |:TodoFilter| above. Tags are multi-valued and
orthogonal to status; due dates are date-only single fields. Both are written
in the task marker area and are documented in |todo2-format-tags| and
|todo2-format-due|.

---------------------------------------------------------------------
4.5 Calendar                                        *todo2-command-calendar*

                                                    *:TodoCalendar*
:TodoCalendar [YYYY-MM]
                Open the calendar float for the current project, optionally
                jumping to a month, e.g. `:TodoCalendar 2026-10`. The grid
                only includes tasks that carry an `@YYYY-MM-DD` due date;
                archived tasks are left out. See |todo2-calendar| for the full
                layout and key behavior.

4.6 Git                                              *todo2-command-git*

The three commands below are also reachable as `:TodoGit sync|review|blame`.

                                                    *:TodoGitSync*
:TodoGitSync    Incrementally scan commits from the last synced commit to HEAD,
                apply the `git.refs` rules and record the commit. With `!`,
                ignore `git.enable`.

(see also |:TodoGit|: `review` / `blame` are the group forms of the two
commands that used to exist as `:TodoGitReview` / `:TodoGitBlame`)

---------------------------------------------------------------------
4.7 Views / jump / AI                                *todo2-command-view*

                                                    *:TodoLinks*
:TodoLinks      Show all backlink markers in the project (QuickFix). With `!`,
                only the current buffer (LocList): `:TodoLinks!`.

                                                    *:TodoJump*
:TodoJump       Dynamically jump TODO ↔ code.

`TodoView float|split|vsplit|edit|close` open / close the TODO window; see
|:TodoView|.

                                                    *:TodoDrawer*
:TodoDrawer     Toggle the task-tree drawer. See |todo2-drawer|.

                                                    *:TodoSet*
:TodoSet        Open the attribute panel for the task at the cursor: status,
                tags and due date in one float, so the three fields live in one
                place instead of three commands. `<CR>` edits the field under
                the cursor, `s` / `t` / `d` edit status / tags / due directly,
                `q` or `<Esc>` closes. Writes go through exactly the same paths
                as |:TodoStatus|, |:TodoTag| and |:TodoDue|; the file format and
                those commands are unchanged.

                                                    *:TodoContext*
:TodoContext [markdown|json]
                Assemble the current task's context for an LLM: content /
                description / status, the code anchor (path, line, optional
                0-based byte column, block type/name/signature and source),
                and the task tree (ancestor chain + subtasks). Copies Markdown
                to the clipboard by default; `json` emits JSON. With `!`, open
                it in a scratch buffer instead of copying. See |todo2-ai|.

                                                    *:TodoMcp*
:TodoMcp        Print the MCP setup info for wiring the todo2 MCP server into
                an MCP client such as pi: the Neovim RPC socket, the bridge
                script path, and a ready-to-run `pi mcp add` command. See
                |todo2-ai|.

---------------------------------------------------------------------
4.8 Grouped entries / renamed commands               *todo2-command-alias*
                                                          *:TodoFile*
                                                          *:TodoView*
                                                          *:TodoTask*
                                                          *:TodoGit*

Low-frequency maintenance commands are grouped so the flat command list stays
short. Members keep their own commands (documented above) and are also
reachable through the group, e.g. `:TodoFile new`.

  :TodoFile new|rename|delete
                    TODO file lifecycle: `new` creates a TODO file, `rename`
                    renames the current one, `delete` removes it.

  :TodoView float|split|vsplit|edit|close|preview
                    Open the TODO view: `float` / `split` / `vsplit` open a
                    floating, horizontal or vertical window, `edit` opens the
                    file in the current window, `close` closes the todo2
                    window, `preview` runs the smart TODO/code preview.

  :TodoTask rename|desc|promote
                    `rename` edits the task content (from code or a TODO
                    line), `desc` edits the body under the task, `promote`
                    deletes the task but keeps its children.

  :TodoGit sync|review|blame
                    Git integration commands.

Every group accepts `!` and a line range where the target command does, and
`:Todo <group> <member>` works as well.

5. KEYMAPS                                                  *todo2-keymaps*

The plugin ships only a few high-frequency smart keys (they apply in TODO /
code-file context and otherwise fall back to native behavior). Every other
action is a `:TodoXxx` command for you to map. There are no built-in
`<leader>m*` mappings; the examples in older docs are user-side suggestions.

---------------------------------------------------------------------
5.1 Global                                          *todo2-keymaps-global*

    <CR>            toggle task status (completed ↔ not completed)
    <S-tab>         cycle status
    <BS>            smart-delete a task
    <BS> (visual)   delete every selected task in one go (subtrees included)
    <S-CR>          edit the linked TODO task content from code
    <C-[>           dynamic jump TODO ↔ code

Example user mappings for the rest: >
    vim.keymap.set("n", "<leader>mta", "<cmd>TodoAdd<cr>",   { desc = "Create task from code" })
    vim.keymap.set("n", "<leader>mvd", "<cmd>TodoDrawer<cr>",{ desc = "Task drawer" })
    vim.keymap.set("n", "<leader>mvc", "<cmd>TodoCalendar<cr>", { desc = "Calendar" })
    vim.keymap.set("n", "<leader>mvf", "<cmd>TodoView float<cr>", { desc = "Open TODO float" })
<

---------------------------------------------------------------------
5.2 TODO files                                      *todo2-keymaps-todo*

Buffer-local mappings provided automatically in TODO files: >
    q                   close the window
    <localleader>n      new task
    <localleader>nc     new subtask
    <localleader>ns     new sibling task
    v <CR>              toggle status of the selected tasks (batch)
    za / zR             expand bodies / expand all
<

---------------------------------------------------------------------
5.3 Drawer                                        *todo2-keymaps-drawer*

Mappings inside `:TodoDrawer`: >
    <CR>            toggle task status
    <S-CR>          cycle status
    <S-tab>         cycle status
    t               select task status (menu)
    T               edit tags (multi-select menu)
    u               set the due date (opens the date panel)
    C               open the calendar on this task's due date (today if none)
    i               attribute panel: status / tags / due in one float
    f               filter tasks (tags, status:..., path:..., due:...)
    F               clear the filter
    s               sort siblings by status (toggle)
`i` (or `:TodoSet` on a TODO line) is the "one concept" entry: instead of
remembering `t` / `T` / `u`, open the panel and edit the attribute you see.
The individual keys keep working and stay documented above.

    <Tab>           jump to the task's location: linked code, or its TODO
                    line for pure/lost tasks
    o               preview the TODO file in a float
    P               preview the task's linked code lines in a float
    e               edit task content
    E               edit task description (body)
    c               copy the current task's context (Markdown, for AI)
    y               yank the task subtree to the task register
    d               cut the task subtree to the task register
    p               paste the task: over a task → as its child; over a file
                    header → at file end
    a               new TODO file
    R               rename the current file group's TODO file
    D               delete the current file group's TODO file (and its tasks)
    <BS>            delete task
    <BS> (visual)   delete every selected task in bulk (subtrees included)
    x               archive the task group (unarchive when on an archived task)
    za / zo / zc    fold / unfold / collapse the current node
    zR / zM         expand / collapse all
    r               refresh
    A               toggle archived tasks in the tree
    ?               toggle this help
    q               close the drawer
<
Tasks marked `↗` have their own code anchor. `↳` means the anchor is inherited
from the parent (`ns` supplements). Plain tasks have no marker; `<Tab>` opens
their TODO line.

`f` prompts for tags, `status:<label|active>` and `path:<substring|glob>` (all
conditions AND); only matching tasks **and their ancestor chain** are shown,
with the file header showing `(hits/total)`. The filter is drawer-local and is
cleared when the drawer closes; `s` sorts siblings by the configured status
cycle (completed/archived last). `:TodoFilter ...` / `:TodoFilter!` /
`:TodoSort` also work while the drawer is focused.

    h / l           previous / next day (stays in the grid while the target is

6. TASK LINE FORMAT                                          *todo2-format*

---------------------------------------------------------------------
6.1 Task lines                                            *todo2-format-task*

Task lines use this format: >
    - [ ] <status>:<id> [@YYYY-MM-DD] [#tag ...] task content
             optional description (indented continuation lines)
<
- Prefixes `- `, `* ` and `+ ` are supported.
- Checkboxes: `[ ]` (todo), `[x]` / `[X]` (done), `[>]` (archived).
- `<status>` is a cycle label (`todo` / `doing` / `blocked` by default);
  `<id>` is a 6-character base36 ID.
- `[@YYYY-MM-DD]` is an optional **due date**, right after the marker and
  before the tags. See |todo2-format-due|.
- `[#tag ...]` is an optional **multi-value tag segment**, right after the
  marker (and due date) and before the content. See |todo2-format-tags|.
- `[>]` marks an archived task. Archived tasks live in the
  `## Archived (YYYY-MM)` section and normally do not appear in the default
  views; restore them with `:TodoUnarchive`.
- Lines indented deeper than a task line form its *description* (body); they
  end at the next task line, or at a line that is not indented deeper. See
  |todo2-format-body|.

Example: >
    ## Active
    - [ ] todo:ab12cd #fix fix login logic
          needs to also handle empty input

          see `src/http_client.rs`
      - [x] todo:34ef56 handle empty input
    - [ ] todo:78ab90 #backend #urgent add documentation

    ## Archived (2026-09)
    - [>] archived:cd34ef completed task
<
No text markers are inserted into code files; code links are maintained in
the store's `locations.code` and rendered through extmark virtual text.

---------------------------------------------------------------------
6.2 Tags                                                 *todo2-format-tags*

Tags are **multi-valued and orthogonal to status**: one task can be `todo`
while carrying `#fix`, `#backend`, etc. Status answers "how far along", tags
answer "what kind / which module".

- Written after the marker (and due date), before the content:
  `- [ ] todo:ab12cd #fix #backend fix login`
- Rendered live as `#fix` text (cyan italic); friendly to editing, search and
  `rg '#fix'`.
- Normalized to lowercase, de-duplicated and sorted (`core.tags`); edits are
  written back to the TODO line.
- Editing `#tag` directly in the TODO file is synced back into the store.
- Shown in the drawer, `:TodoLinks` quickfix, `:TodoLinks!` location list,
  and code-file task markers.
- `:TodoTag` sets/adds/removes tags; see |:TodoTag|.

---------------------------------------------------------------------
6.3 Due dates                                             *todo2-format-due*

A due date is a single field with a **date only** (no time), so ordering and
sorting are plain string comparison with no timezone/DST drift.

- Written after the marker, before the tag segment:
  `- [ ] todo:ab12cd @2026-07-01 #fix fix login`
- Invalid dates (`2026-02-30`) degrade to plain text; the line still parses.
- `@date` is only recognized **right after the task marker** (before
  tags/content). A date written at the end of the title stays plain text and
  is never treated as a due date — any rewrite of the line notifies a warning
  instead of doing it silently.
- Display: the inline `@date` is hidden by default (`conceal_due = false`
  turns that off) and the due date moves into an **end-of-line metadata band**
  after the last-modified time:
  `- [ ] fix login    ● ↻10-30 · 11-02` (`↻` marks the last modification,
  shown first; the due date follows, urgency-coloured; completed/archived
  tasks show their completion/archive time instead of `↻`). Same year renders as `MM-DD`, cross-year as
  `YYYY-MM-DD`. The raw `@date` stays hidden until the cursor sits on it, so
  hand-editing still works and the line reads as "content first, date at the
  end". The file text never changes.
- Coloured by urgency: overdue red, today/within 3 days amber, later blue;
  completed and archived stay uncoloured.
- Editing `@date` directly in the TODO file is synced back into the store.
- `:TodoDue` sets/clears it (no argument opens the date panel); see
  |:TodoDue| and |todo2-due-panel|.
- Completed/archived tasks keep their due date (the view filters them out),
  so "was due last week, done today" stays auditable.
- `:TodoFilter due:overdue` / `due:today` / `due:week` / `due:month` /
  `due:none` / `due:2026-07` / `due:<2026-07-01`
- MCP: `task_create` accepts `due`; `task_update` has a `due` write action
  (empty string clears); task summaries include `due`.

---------------------------------------------------------------------
6.4 Description (body)                                   *todo2-format-body*

A title is one line; longer notes (specs, checklists, even a small tech doc)
go on **indented continuation lines** right under the task — plain Markdown,
no extra syntax: >
    - [ ] todo:ab12cd add jar-based cookie refresh
         Needs:
         1. read the jar path from config
         2. refresh on a timer

         See `src/http_client.rs`
      - [ ] todo:34ef56 subtask (a task line ends the body)
<
- Any non-task line **indented deeper than the task** belongs to its body;
  blank lines are allowed, so multi-paragraph bodies work.
- Body indentation aligns with the **rendered task text** (task indent + 5);
  it is normalized on save (`description.format_on_save`).
- Bodies are **collapsed by default** in TODO files; `za` / `zR` expand them.
  The fold shows `◻ title  ¶ N 行`.
- In a TODO file `:TodoDesc` edits the body **inline**; in a code file or the
  drawer it uses a multi-line float.
- Deleting a task removes its body too (body and task are strongly bound).
- Archiving moves the body with the task.
- Stored as `core.description`; the file stays the source of truth.

7. FEATURES                                                *todo2-features*

---------------------------------------------------------------------
7.1 Code ↔ TODO links                                        *todo2-links*

Each task is linked to two locations:

- **Code location** (`locations.code`): file path + line number + optional
  byte column (`col`, 0-based; shown as 1-based) + code-block context.
- **TODO location** (`locations.todo`): TODO file path + line number.

On long lines the anchor keeps the exact cursor column (`col` / `end_col`,
0-based bytes) plus a `snippet` used to re-locate the token after in-line
edits. Jump, preview and rendering all honor the column; it is a soft hint and
does not change anchor identity (which is still the line fingerprint).

Code files render task status next to the linked line via extmark virtual
text; TODO files manage tasks through task lines.

---------------------------------------------------------------------
7.2 Code-block context                                      *todo2-context*

When creating a task, the enclosing code block (function/class/method/struct,
etc.) is detected automatically, with three fallback levels:

1. **Treesitter** (preferred)
2. **LSP documentSymbol**
3. **Indent detection** (last resort)

Context refreshes automatically on refactors such as function renames, keeping
markers anchored to the correct code block.

---------------------------------------------------------------------
7.3 Status                                                  *todo2-status*

Active statuses are **user-configurable** (`status.cycle`, see
|todo2-config|); `completed` / `archived` are fixed terminal states.

- `<CR>` toggles completed ↔ not completed
- `<S-tab>` cycles through the configured cycle
- `:TodoStatus` opens the status selection menu

Statuses express **progress only** (`todo` / `doing` / `blocked` by default).
Task type / module belongs in tags (`#fix`, `#backend`).

---------------------------------------------------------------------
7.4 Live code-line tracking & rendering                    *todo2-tracking*

When code files insert/delete lines, all linked tasks' line numbers are
updated incrementally via buffer `on_lines`, so markers always follow the
code.

When a code block is deleted outright (or moved and can no longer be located),
the marker does not drift to an unrelated line: it stops rendering in the code
buffer and the TODO line shows `⚠`. Re-link it with `:TodoLink <id>`, or
delete the whole task with `<BS>`. `:TodoDoctor` / `:TodoSync!` help
diagnose and rebuild.

Anchor state is tracked internally as three values — `ok` (verified),
`stale` (not verified yet, the default) and `lost` (verified and gone) — but
**the UI only distinguishes two**: trusted (no badge) and needs attention
(`⚠ anchor lost`). You never need to know the internal values. `stale` means "nobody has looked yet", not a problem, so it
is never rendered; the single judgment entry is
`require("todo2.store.task.core").is_anchor_lost(task)`, used by the code
markers, the drawer and the QuickFix/archive views alike.

When several tasks share the same code line, their markers render **together**
(instead of overwriting each other): `above`/`below` stack one virtual line per
task, and `inline` joins them with `│`. When a parent and its subtask share the
line, they are ordered by hierarchy: the parent (group) comes first and
descendants are indented with `└`. When too many tasks share a line, only the
most relevant one is shown with a `+N` badge; the cap is controlled by
`code_render.max_lines` (default 3). The representative prefers the group
(ancestor), otherwise `doing > todo > blocked > completed > archived`; the sign
column shows its status. Pressing `<C-[>` on a code line with several tasks
opens a picker to choose which one to jump to; with a single task it jumps
directly.

`above`/`below` markers are extmark virtual lines. By default
(`code_render.virt_lines_overflow = "trunc"`) they do **not** scroll
horizontally: they stay at the window's left edge while the code scrolls, so
the label remains visible on long lines. Set it to `"scroll"` and use
`:set nowrap` if you want the virtual lines to scroll with the code;
`"auto"`/`"wrap"` control wrapping. The option only affects `above`/`below`,
not `inline`.

---------------------------------------------------------------------
7.5 Drawer                                                  *todo2-drawer*

`:TodoDrawer` (or `:Todo` with no argument) toggles a right-hand panel (or a
bottom split, per `drawer.position`) showing the project's task tree grouped by
TODO file. Keys are listed in |todo2-keymaps-drawer|.

The drawer shows archived tasks when toggled with `A`
(`archive.include_in_render` controls the default). `C` opens the calendar on
the selected task's due date (today when it has none). In Visual mode,
`<BS>` deletes every selected task in bulk, subtrees included.

---------------------------------------------------------------------
7.6 Calendar                                              *todo2-calendar*

`:TodoCalendar [YYYY-MM]` (also `:TodoCalendar` with no argument) opens the
calendar float for the current project. Only tasks with an `@YYYY-MM-DD` due
date are included; archived tasks (`[>]`) are left out.

- **Month grid**: every day is its own background-coloured block (no border
  characters). Line 1 is the day number, pinned to the first column so it
  never jumps; line 2 is the title of the most urgent open task (`▎` bar +
  truncated title). Counters sit right-aligned on line 1: `● 2` unfinished
  (green) and `○ 1` completed (grey), omitted when zero and capped at `9+`.
  Busy days get a heavier tint (3 levels); today's date is highlighted as
  **text** (accent colour + bold, no background block); the selected day gets
  a brighter whole-cell block. Adjacent-month days stay dim and uncounted; a
  trailing week that belongs entirely to the next month is trimmed.
- **Side panel**: when the terminal is at least 116 columns wide, a panel for
  the selected day (counts + task list) is appended to the right and follows
  `j`/`k`.
- **Day list** (`<CR>`): tasks due that day, unfinished first, completed greyed
  out, task id right-aligned; `<CR>` jumps to the task's code anchor (falls
  back to the TODO line when nothing is linked), `b`/`Esc` goes back.
- The float sizes itself to its content and stays centred (also on
  `VimResized`); too-small screens fall back to a compact one-line-per-week
  layout. It disables other plugins' decorations (indent guides, sign/fold
  columns, `statuscolumn`, spell, `treesitter-context`, ...) so the grid stays
  clean.
- Keys: see |todo2-keymaps-calendar|.
- UI text is English only (no i18n); icons are configurable via
  `calendar.mark_icon` / `calendar.done_icon`.
- Config: `calendar = { first_day_of_week = "monday", mark_icon = "●",
  done_icon = "○", winblend = 0, show_completed = true }`. With
  `show_completed = false`, completed tasks are hidden from the grid, the
  counters and the panels.

---------------------------------------------------------------------
7.7 Archive                                                *todo2-archive*

Archiving is a **move, not a discard**: the task group's lines move into the
`## Archived (YYYY-MM)` section of the TODO file and their status becomes
archived (tasks stay in the store). The section is the single source of truth.
IDs are preserved and the operation is reversible.

- `:TodoArchive` archives the task group at the cursor (its whole subtree);
  its lines (task + body) move into the `## Archived` section.
- `:TodoUnarchive` picks an archived group and moves it back into the active
  section of its TODO file (statuses restored).
- `:TodoArchiveView` / `:TodoArchiveView!` show archived tasks as a tree / a flat
  anchor list (QuickFix).
- The task-tree drawer shows archived tasks when toggled with `A`.
- The code anchor is **frozen** (code files are never modified); the cached
  snapshot is re-resolved through `relocate` when needed.
- `archive.allow_unfinished` (default `true`) controls whether a tree with
  active tasks may be archived; `:TodoArchive!` overrides it.

---------------------------------------------------------------------
7.8 Git integration                                          *todo2-git*

Turns task references in commit messages (e.g. `todo:ab12cd`) into status +
metadata, and adds a pre-commit self-check. Off by default; enable explicitly
with the `git` config table (see |todo2-config|).

- `:TodoGitSync` scans from the last synced commit to HEAD, applies the `refs`
  rules and records the commit; `!` bypasses `git.enable`.
- Within one message the latest reference wins; only the essential `todo:<id>`
  rule ships by default.
- `:TodoGit review` lists tasks whose code anchors sit in dirty files
  (pre-commit check); pair with `:TodoFilter #git:dirty`.
- `:TodoGit blame [id]` shows the commit history of a task's code anchor.
- When an anchor goes stale/lost, the last commit that touched that code is
  recorded and shown as `⚠ 锚点已过期（1a2b3c4 by alice）` in viewer / drawer.
- Derived tags: `:TodoFilter #git:dirty`, `:TodoFilter #git:branch:main`.
- `git.trigger = "on_open"` syncs when a TODO file opens; `show_metadata`
  controls the linked-commit display.
- MCP: `task_link/complete_commit` (close tasks by sha or message); works
  regardless of `git.enable`.

---------------------------------------------------------------------
7.9 Preview / progress / smart jump                     *todo2-preview*

`:TodoView preview` previews the tasks for the current code line in a focused
view: the ancestor chain (middle levels elided beyond 3), the target task with
its description expanded, and its direct children (descriptions folded, at
most 6 with a `… 还有 N 项` overflow line). When several tasks share the
anchor, each gets its own block (current one first); multiple blocks are tiled
with equal size and packed edge-to-edge. The number of tiles is chosen
geometrically; if the screen is too small the blocks fall back to a single
scrollable window (nothing is dropped). `preview.max_blocks` (default 20) is a
safety upper bound only.

Opening a TODO file in a floating window shows a task completion progress bar
in the footer; it refreshes in real time when task statuses change.

`<C-[>` dynamically jumps between code ↔ TODO.

==============================================================================
8. AI CONTEXT / MCP                                              *todo2-ai*

`:TodoContext` assembles the current task into text you can feed to an LLM:
task content / description / status, the **code anchor** (path, line, optional
column, the code block's type/name/signature and its source), and the task
tree (ancestor chain + subtasks).

- Markdown to the clipboard by default; `:TodoContext json` emits JSON,
  `:TodoContext!` opens it in a scratch buffer.
- The anchor carries a state: `ok` / `stale` (not verified yet, the default)
  / `lost` (no source attached). The display layer collapses `ok` and
  `stale` into "trusted" and only badges `lost` (see |todo2-tracking|).
- `inherited` marks a supplement that inherits its anchor from the parent.
- The assembly layer `todo2.ai` is client-agnostic.

MCP (for pi and other agents) ~

**Off by default.** Set `ai = { enabled = true }` (see |todo2-config|) to
publish the endpoint automatically on setup; `:TodoMcp` prints the connection
info and publishes on demand. `:TodoContext` (copy a task's context for a
model) works regardless — only the MCP bridge is gated.

The plugin ships a minimal MCP stdio server exposing the tasks as five
action-dispatch tools:
- Read: `task_query` with `action = "list" / "search" / "tree" / "info" /
  "context"` (marked readOnly)
- Write: `task_create` (`task` / `tree` / `note` / `file`), `task_update`
  (`content` / `status` / `due` / `tags_set` / `tags_add` / `tags_remove`),
  `task_link` (`link` / `verify` / `complete_commit`), `task_remove` (`delete`
  / `archive` / `unarchive`)

Each tool takes a required `action` plus that tool's flat params; missing
required params are validated at runtime with a clear error.

Read side:
- `task_query/list` / `task_query/search` accept `status` / `tag` filters and
  `limit` / `offset` pagination; both can include archived tasks
  (`include_archived`); `search` needs `query`.
- `task_query/tree` returns `{files:[{path, roots:[{id,content,status,tags,
  anchor?,children?}]}]}` (nodes carry anchors); pass `include_archived` to
  append the `(archived)` group.
- `task_query/info` returns the project name/dir, the TODO files with task
  counts, and active/archived totals.
- `task_query/context` (needs `id`) returns markdown by default, or JSON when
  `format = "json"`.
- Successful calls also return `structuredContent` alongside the text payload.
  The array-returning actions (`task_query/list` / `task_query/search`) wrap
  their array as `structuredContent.items` (the spec requires structured
  content to be a JSON object, not an array).

Write side:
- Writes go through the **same code path as the Ex commands** (tag edits via
  the `:TodoTag` handler, due edits via the `:TodoDue` handler), so MCP and
  interactive edits cannot drift apart.
- `task_create/note` creates an **anchor-less** checklist item (for notes /
  ideas); `task_create/task` and `task_create/tree` are for tasks that *are*
  about code.
- `task_update/content` rewrites a task's text and its TODO line.
- `task_remove/delete` / `archive` / `unarchive` close the loop: archive moves
  a subtree into the `## Archived` section, unarchive moves it back. Archived
  tasks must be unarchived before deletion.

**Hard rule: `task_create/task` / `task_create/tree` require a code anchor**
(`anchor = {path,line,col?}` pointing at the exact 1-based line of a real
symbol; `col` is an optional 0-based byte offset). `task_create/note` is the
explicit escape hatch for anchor-less items. Anchors are pre-checked (file
exists, line in range) and **re-verified immediately after write**, so the
returned anchor state reflects reality (`ok` / `lost`). Use
`task_create/tree` for a pipeline/stage breakdown, and `task_link/verify` to
re-locate stale/lost anchors at any time.

`task_create/task` is **idempotent** by default: a task with the same content
under the same parent is reused (returns `deduped: true`), so agent retries
don't duplicate. Pass `allow_duplicate: true` to force creation.

Bridge vs standalone ~

The default **bridge** mode connects back to the **live Neovim** (single source
of truth) instead of reading store snapshots.

**Standalone mode (no Neovim required).** Set `TODO2_MCP_STANDALONE=1` (or
`TODO2_MCP_MODE=standalone`, or pass `--standalone`) and the server boots the
todo2 data layer *inside its own process*: the TODO files on disk are the
source of truth and no editor needs to be running — Neovim becomes a pure UI.
The project is taken from the server's working directory; override it with
`TODO2_PROJECT_DIR=<dir>`. Point at nvim-store3 / extra runtimepath entries
with `TODO2_NVIM_STORE3=<path>` and `TODO2_RUNTIME=<dir>[:<dir>…]` when they
are not siblings of the plugin. Read-only mode and all tool validation still
apply.

Set `TODO2_MCP_READONLY=1` to run the server in read-only mode (all write
actions are refused). When several Neovim instances are open, `:TodoMcp`
publishes a `project → socket` registry; set `TODO2_PROJECT=<name>` to pin the
bridge to one project's instance instead of the last-published socket.

Run `:TodoMcp` to print the setup command, e.g.: >
    # bridge mode (needs a live Neovim with the plugin)
    pi mcp add todo2 --env TODO2_NVIM=<socket> -- nvim --headless -u NONE -l <plugin>/mcp/todo2-mcp.lua
    # standalone mode (no live Neovim needed)
    pi mcp add todo2 --env TODO2_MCP_STANDALONE=1 -- nvim --headless -u NONE -l <plugin>/mcp/todo2-mcp.lua
<
Add `--env TODO2_MCP_READONLY=1` for read-only, or
`--env TODO2_PROJECT=<name>` to pin a project. Setting
`"exposure": "direct"` on the `todo2` entry in `~/.pi/agent/mcp.json` makes
the model see the tools directly.

9. DATA-SHAPE CONTRACT                                         *todo2-schema*

The `*.todo.md` files are always the source of truth, so anything derived from
them can be rebuilt by reconcile (old namespaces are simply hard-cut and
purged). The only data worth protecting is the part of the store that **cannot
be rebuilt**: timestamps, delete tombstones, orphan snapshots and anchor
verification state.

- `store/schema.lua` is the single normalization entry point for those: legacy
  fields stripped, defaults filled in, invalid dates/unknown statuses dropped,
  locations validated — all inside `normalize_task` / `normalize_facts`.
- Adding a field only needs a default in `schema.TASK_CONTRACT` +
  `normalize_task`; `test/schema.lua` asserts the contract (and turns red when
  you forget). No data migration required.
- The shape version lives in `facts.meta.schema_version` (currently `1`) and
  only **marks** the data, it never converts it — it is there so a future
  incompatible change can recognize old stores.
- Rule of thumb: new field / new key → normalization default is enough;
  renamed key, changed semantics or split/merged dictionary sets → that is
  when a real migration (backup + `:TodoMigrate`) is worth building, not
  before; TODO file syntax changes → **never migrate files**, parse compatibly
  and write back in the new format.

11. WORKFLOWS                                              *todo2-workflows*

CREATE A TASK FROM CODE ~

1. Put the cursor on the code line to link.
2. Run `:TodoAdd` (map it, e.g. `<leader>mta`).
3. Choose a tag → choose a TODO file.
4. The task is written to the TODO file with the code location and enclosing
   code-block context recorded.

ADD A TASK IN A TODO FILE ~

Tasks added directly in the TODO file do not write to code files:

- `<localleader>n`: new independent task (plain checklist task, no context)
- `<localleader>nc`: new subtask of the current task (a supplement)
- `<localleader>ns`: new sibling of the current task

`<localleader>n` / `<localleader>ns` are plain checklist tasks unrelated to
code. A `<localleader>nc` subtask has no code anchor of its own and **inherits
the context of its nearest ancestor**: under a plain parent it is plain too;
under an anchored parent its `<Tab>` jumps to the parent's code. Use
`:TodoLink` to attach code explicitly.

TOGGLE STATUS IN CODE ~

With the cursor on a linked line in a code file, press `<CR>` to toggle the
completed status; the code-side marker (extmark) updates immediately.

ARCHIVE A TASK GROUP ~

Archiving is a move, not a discard: the task group's lines are moved into the
`## Archived (YYYY-MM)` section of the TODO file and their status becomes
archived (they stay in the store). The section is the single source of truth;
the operation is reversible (ids are preserved, statuses restored on
`:TodoUnarchive`). Code files are never modified; anchors are frozen and
re-resolved when shown. Use `:TodoArchiveView` / `:TodoArchiveView!` to review
archived tasks, and the drawer key `A` to include them in the tree.

FIND AND FIX A LOST ANCHOR ~

If a task's TODO line shows `⚠`, its code location can no longer be found.
Run `:TodoDoctor` to check store health, `:TodoSync!` to rebuild the store
from the TODO files, then `:TodoLink <id>` to bind the task to the correct
code line again (or `<BS>` to delete it).
